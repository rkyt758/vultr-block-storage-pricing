## Vultr Block Storage 究竟是什么

块存储是一种原始磁盘云盘卷，其行为类似于物理附带的驱动器。你将其挂载到虚拟机，进行格式化并挂载，然后用于文件系统、数据库、日志或备份。Vultr 的实现是分布式的，并在高可用集群中进行复制，设计可用性目标为 99.99%，因此单个硬件故障不应该导致你的数据丢失。

它的有用之处在于：存储与计算是独立扩展的。如果实例的本地磁盘满了，你可以在不更改计划或迁移机器的情况下添加云盘卷。你也可以稍后增大云盘卷容量，而无需触碰本地磁盘。

你什么时候*不*需要它？如果你存储的是静态内容——媒体文件、冷备份、通过 HTTP 服务的归档文件——那么对象存储是更合适的工具。块存储适用于你的操作系统或应用程序需要实际磁盘的情况。如果你的实例自带的磁盘足够大，添加云盘卷只是额外的月度支出。

## 性能限制：数字意味着什么（以及突发限制）

Vultr 公布的目标是 NVMe 为 10,000 IOPS 和 400 MiB/s，HDD 为 500 IOPS 和 100 MiB/s。这些是规划时的上限，而不是对每种工作负载的保证——实际性能因实例类型、I/O 模式和云盘卷大小而异。

大多数摘要忽略的一点是：NVMe 云盘卷具有突发模式，允许你超出基准最多 50%——但仅限最长 60 秒，且突发功能随后需要一段活动减少期来重置，然后才能再次使用。

在实践中这意味着：短时间的激增没问题。仪表盘加载报告或执行一分钟重度读取的定时任务——突发可以处理这些。但如果你打算运行持续的高 I/O（一个不断进行写入操作的繁忙数据库），请将你的预期调整到 10,000 IOPS 的基准，因为突发无法支撑你度过整个下午。

如果你想亲自验证性能，而不是单方面信任任何数字，Vultr 发布了基于 `fio` 的基准测试分析，通常的调节手段也适用：块大小、缓存、I/O 调度和你的 VPS 计划都会影响实际数字。

## 如何创建、挂载并安装云盘卷

设置只需几分钟。简短版本：

1. **创建云盘卷。** 在 Vultr 控制台中：Products → Cloud Storage → Block Storage → Add Block Storage。选择 NVMe 或 HDD，选择位置，拖动大小滑块，添加标签，然后确认。等待状态显示为 Active。
2. **将其挂载到实例。** 云盘卷一次挂载到一台服务器，且服务器必须位于同一位置。打开块存储列表，点击云盘卷旁边的铅笔图标，选择服务器，然后点击 Attach。
3. **在操作系统内进行格式化和挂载。** Vultr 不会为你创建文件系统。

在 Linux 上，第一个挂载的云盘卷显示为 `/dev/vdb`（下一个为 `/dev/vdc`，依此类推）。使用 `lsblk` 确认，然后：

bash
lsblk                                               # find your volume, e.g. /dev/vdb
parted -s /dev/vdb mklabel gpt
parted -s /dev/vdb unit mib mkpart primary 0% 100%
mkfs.ext4 /dev/vdb1
mkdir /mnt/blockstorage
echo '/dev/vdb1 /mnt/blockstorage ext4 defaults,noatime,nofail 0 0' >> /etc/fstab
mount /mnt/blockstorage


Vultr 重复并值得重复的警告：这些命令会清除目标设备上的所有内容。在格式化之前请仔细检查设备名称——在错误的磁盘上运行 `mkfs` 是无法恢复的错误。

在 Windows 上，这是熟悉的操作流程：Computer Management → Storage → Disk Management，将新磁盘（通常是 Disk 1）联机，使用 MBR 或 GPT 初始化，然后运行 New Simple Volume 向导。

如果你想自动化其中任何步骤，同样的操作可以通过 Vultr API（`POST /v2/blocks`）、CLI 和 Terraform 完成。Vultr 自己的 CLI 示例：`vultr-cli block-storage create --block-type high_perf --region ewr --size 80`。

每个服务器一个云盘卷听起来限制很大，直到你了解规则的另一面：单个 Compute 实例最多可以挂载 16 个云盘卷，每个云盘卷都作为独立的磁盘出现。👉 [在 Vultr 上创建你的第一个块存储云盘卷](https://www.vultr.com/products/block-storage/?ref=7268283)

## 真正重要的细则

这些细节存在于警告和支持文档中，而不是销售文案中，且每一条都曾给用户带来过麻烦：

- **Vultr 不保留块存储的备份。** 这是最大的问题。Vultr 对服务器实例的快照和自动备份不包含挂载的块存储云盘卷。如果你删除了云盘卷，或者其中的数据损坏了，没有 Vultr 端的副本可供回退。请运行你自己的备份程序，并将其存储在实例之外。
- **永远在同一区域。** 云盘卷只能挂载到同一区域的实例，且你以后无法将云盘卷移动到另一个区域。创建云盘卷时请选择服务器的位置，而不是之后。
- **扩容容易；缩容不易。** 你可以在控制台中向上调整云盘卷大小并在操作系统中扩展文件系统——但调整大小需要重启挂载的实例。没有原地降级选项，因为缩容存在数据丢失的风险；官方建议缩小云盘卷的方法是将文件迁移到新的、更小的订阅中。
- **fstab 陷阱。** 在从 Linux 实例分离云盘卷之前，请从 `/etc/fstab` 中删除其条目——否则操作系统可能会在启动时因等待一个已不存在的磁盘而卡住。（挂载行中的 `nofail` 选项是第二道防线，而非替代品。）
- **不支持 Bare Metal。** 块存储仅挂载到虚拟 Cloud Compute 实例。如果你在 Vultr Bare Metal 上，此产品不适用于你。

## 计费工作原理

块存储在存在期间按小时计费，上限为月度费率。Vultr 的模型将月度费率除以 672 小时（一个 28 天的月份）；运行整月的云盘卷成本正好是月度价格，而你在月中删除的云盘卷仅按其存在的小时数收费。账单在每月的 1 日寄出。

两个相关的注意事项。首先，停止计费的方法是删除云盘卷——分离它并不能停止计费，因为云盘卷仍然存在并继续预留容量。其次，同样的“停止仍计费”逻辑也适用于实例：关机的 VM 仍会继续预留 RAM、磁盘和 IP 资源，所以如果你要搁置一个项目，请删除不使用的内容，而不是仅仅停止它。

## 一段话说清块存储与对象存储的区别

块存储是一个磁盘：你对其进行格式化、挂载，你的数据库或文件系统驻留在上面。对象存储是一个桶：数据作为对象输入，并通过 API 访问，这适用于大规模静态数据——备份、媒体库、归档文件。如果你的工作负载是“我的 Postgres 需要更多空间”，你需要块存储。如果是“我有 3 TB 没人编辑的图片”，那么对象存储或便宜的 HDD 块存储将比支付 NVMe 费率更好地为你服务。

## 常见问题解答

**一个云盘卷可以同时挂载到两台服务器吗？**
不可以——云盘卷一次只能挂载到一台服务器。要移动它，请在旧服务器上卸载（在清理 fstab 后），分离，然后挂载到同一区域的新服务器上。

**一个实例可以有多少个云盘卷？**
最多 16 个，每个都显示为一个独立的磁盘设备。

**我可以不停机调整云盘卷大小吗？**
不可以。扩大云盘卷需要重启其挂载的实例。请将调整大小安排在维护窗口内。

**数据是否加密？**
是的——Vultr 加密传输中和静态的块存储数据，根据其配置文档使用 AES-256。你可以在其之上添加自己的应用层或 OS 级加密。

**Vultr 会为我备份块存储吗？**
不会。实例快照和备份不包含挂载的云盘卷，且云盘卷本身也没有 Vultr 管理的备份。

**如果我的服务器与云盘卷不在同一区域怎么办？**
你无法挂载它。云盘卷和实例必须共享一个区域，所以请从一开始就在服务器的位置创建云盘卷。
